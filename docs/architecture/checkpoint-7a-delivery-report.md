## 6. Independent review

Reviewer personas selected per the `AGENTS.md` table, matched to what this checkpoint actually changed. Three were used because 7A is simultaneously schema-heavy, caregiver-facing, and privacy-affecting:

- **Child-privacy reviewer** — outbound query contents and child-data minimization. **Verdict: contract holds.** Traced the full path from typed label to HTTP request; the discovery port is typed to accept only a closed enum, so no raw label can reach an outbound request by any typed or dynamic path. Findings addressed below.
- **Staff engineer** — schema, ownership scoping, idempotency, concurrency. Nine findings; six fixed, four deferred with reasons in section 8.
- **Product designer** — mockup fidelity, accessibility, copy discipline. Found the scope gap and the silent-failure defects below.

Product truth was carried by the lead against section 2.3 and is re-presented here for the owner gate.

### Defects found by review and fixed

1. **Two mutations reported success on failure.** `endInterest` and `respondToTopicPrompt` never checked `response.ok`, reloading as though the write succeeded — telling a caregiver a topic confirmation was recorded when it may not have been. All mutations now have real error paths with `role="alert"`; a failed confirmation keeps the prompt open and states the topic is still private.
2. **Duplicate topic codes permanently blocked recommendation requests.** Two current interests reaching one closed code through different aliases produced a duplicate source code, failing snapshot validation for every future request for that child. Now collapsed deterministically, with a regression test.
3. **Mutation-ID overflow.** Derived suffixes meant an ID over 82 characters failed validation mid-save, after the age range had already committed. Capped at 80, with a test asserting nothing is written on rejection.
4. **Sync race could wedge a profile.** End-mutation IDs are now keyed by phase ID rather than code.
5. **`coverage_error` was unreachable.** A provider outage recorded no coverage at all, so an outage could be misread as genuine low coverage when judging the matrix. Failed attempts now record `coverage_error`, and the dev preview refuses to report data from any non-completed attempt.
6. **ISBN dedupe was not normalized.** Hyphenated and unhyphenated forms of one ISBN did not match; invalid ISBNs were usable as dedupe keys. Both corrected.
7. **Remembered books dropped their subject and cover.** The subject is a section 2.3 invariant and the cover was declared but never queried. Both now render; genuinely missing covers stay visibly missing.
8. **Raw enum codes were shown to caregivers.** `fairy_tales` reached the UI via a string transform. A caregiver-facing display-name dictionary now backs every topic prompt.
9. **Settings displayed unsaved form state as saved** (found by lead self-review). Abandoning an edit showed unsaved selections as persisted.
10. Missing `Required` badges and validation messaging; topic input not collapsing at 600px; the settings-only yellow accent leaking onto first-run setup.

### Scope gap found and closed

`Add a book that worked` had no UI. The proposal defers only `More like this book` to Checkpoint 8; this entry point is explicitly in 7A scope. Now implemented: title search, verified-work selection, and an unselected subject choice, creating a durable `worked_for_us` observation with no shelf, reading-event, or reaction side effects — asserted directly in tests.

## 7. Privacy and accessibility evidence

Outbound requests contain exactly four fixed parameters and a query expression drawn from the frozen dictionary; the adapter rejects any code outside it before a request is built. Verified independently: zero `console.*` calls in `src/`, one outbound URL in the candidate path, no raw provider payload column exists, and shared metadata tables carry no household or child foreign key. Child deletion cascades through every child-owned private record, now asserted explicitly.

Accessibility: all error paths announce via `role="alert"`; the disabled save button is explained by `aria-describedby`; the age-range group carries `role="group"`; touch targets meet 44px; focus-visible styling is consistent.

## 8. Known limitations and unresolved decisions

1. **The coverage matrix has not been run** (section 4), because Open Library was down. The sole-provider decision cannot be confirmed or refuted until it is. This is the single largest open item and is not closed by this checkpoint's approval.
2. **`runCandidateDiscovery` has no transaction boundary.** A process crash mid-run leaves an attempt at `started` with partial rows. A DB transaction cannot span the HTTP calls; the correct fix is a stale-attempt sweep. The visible symptom is mitigated — the preview refuses to report untrustworthy attempts.
3. **`attemptNumber` TOCTOU race** surfaces a raw Prisma unique-violation instead of a domain error. The constraint prevents corruption; this is error-handling polish.
4. **N+1 queries** in candidate hydration. Not yet wired to a live route; should be addressed before it is.
5. **No page-scoped offline guard** on Reading profile; the global banner's copy is shelf-specific.

Items 2 through 5 were accepted by the owner as deferred rather than blocking, and are recorded as required carry-forward work in the Checkpoint 7B section of `CODEX_BUILD_PLAN.md` so they cannot be lost.
6. **Only 13 topic codes.** Real caregiver phrasing will frequently miss the dictionary and fall back to the generic corpus. This is the known limitation section 6.3 predicts and Checkpoint 11A is designed to measure.
7. **`ChildProfile` creation is not retry-idempotent** — it has no `clientMutationId` column, which the approved schema addition did not include.
