# V0.1 scope

V0.1 ends only after Checkpoint 11 is explicitly approved.

## V0.1 must do

- Support one protected household and one child profile.
- Store an optional nickname, coarse age or reading-stage band, current interests, historical interest phases, and optional content preferences without a legal name or exact birthdate.
- Generate a first bag from the age or stage band plus either one current interest or one verified reference work; do not require shelf construction or five prior books.
- Add verified books using manual ISBN, title, author, camera barcode, and batch scanning workflows.
- Give each family book one current shelf status: owned, borrowed, or wishlist. Discovery, suggestion, recommendation, and reading history remain separate facts.
- Record reading-session outcomes or explicit reading decisions as finished, reread, stopped, or internal rejected `ReadingEvent` records only after explicit user action. Consumer copy for rejected is `Decided not to read`.
- Record save, `Not for us`, catalog-open, replacement, and attribution interactions as `RecommendationAction` records.
- Treat borrowed and returned as explicit shelf-relationship transitions, and child or caregiver selection as provenance on the relevant action or encounter, not as reading events.
- Keep reading events append-only and correct them through auditable retract or replace amendments.
- Keep optional child and caregiver reactions separate from each other and from reading events.
- Never preselect a reading event or reaction.
- Show chronological book history and derived reread counts from valid events.
- Store durable preference observations and request-scoped recommendation references without implicit shelf, history, event, reaction, status, or borrowing side effects.
- Source, hydrate, normalize, deduplicate, and review recommendation candidates from verified provider records.
- Show deterministic taste evidence that distinguishes current and historical interests, child evidence, caregiver evidence, family references, and missing evidence.
- Generate persisted, explainable 3-5-work normal bags targeting five, honest 1-2-work limited-pool results, and recoverable zero-result states.
- Record explicit recommendation outcomes and attribution.
- Open honest Johnson County Library catalog searches without claiming availability, holds, current loans, history, or authentication.
- Provide a refined responsive Bright Snap shell and truthful loading, empty, limited, error, permission, external-handoff, and offline-warning states.
- Run on a protected hosted HTTPS preview backed by managed PostgreSQL before camera testing.
- Include privacy-conscious activation, recommendation-quality, and reliability measurement for household alpha.
- Include literal Windows setup, deployment, migration, backup, restore, rollback, monitoring, deletion, export, and operations instructions.
- Require human approval after every checkpoint and a scoped Git commit and GitHub push after that approval.

## V0.1 will not do

- Import library checkout history or log in to a library account.
- Store library credentials, card numbers, or PINs.
- Place holds inside Bookkin or claim real-time availability.
- Store preferred branches or claim branch filtering.
- Support multiple caregivers or multiple children.
- Expose public child profiles, social features, leaderboards, streak pressure, or reading assessments.
- Include a general-purpose chatbot.
- Recommend books from an AI-generated universe.
- Implement an LLM for candidates, scoring, taste evidence, composition, or explanations.
- Implement PWA installability, a service worker, offline reload, offline writes, or private-response caching.
- Require a custom domain or DNS for household alpha.
- Introduce native applications, microservices, or production-scale recommendation infrastructure.
- Open public registration; it requires a separately specified future checkpoint and is authorized by neither Checkpoint 12A nor 12B.
- Begin public-acquisition implementation before explicit authorization to start Checkpoint 12B, publish before final 12B approval, or expand a multi-household beta before the applicable Checkpoint 12C gate.
- Add billing, ads, affiliates, sponsored ranking, or child-data monetization.
